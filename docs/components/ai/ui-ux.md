# AI 弹窗 UI 与用户体验规范

更新日期：2026-10-14。适用范围：平台 AI 助手的浮窗、右侧抽屉与全屏模式，以及其中的问答、附件、工具反馈、填写预览、历史会话。

本文是后续调整的共同依据。目标是让用户读得清楚、知道当前状态、顺手完成操作，并在流式输出和布局切换时保持阅读位置。

## 1. 范围与原则

本轮只调整前端呈现与交互反馈。保留现有模型、提示词、工具能力、API、附件解析、字段映射、填写确认、会话生命周期、首句抑制和首问选择规则。Java 后端不涉及修改。

- 先保证正文可读，再控制信息密度。辅助文字不能依靠过小、过浅来降低层级。
- 发送、停止与输入相关反馈放在输入区，结果和确认留在对应消息或卡片中。
- 流式输出不抢走用户正在阅读的位置；主动发送和返回底部才恢复跟随。
- 同类卡片采用相同的字号、边距、颜色与操作规格。
- 沿用现有 SDK 的输入、附件和键盘能力，不另造一套聊天输入框。
- 动画服务于状态变化；拖动要跟手，减少动态效果的系统设置应生效。

## 2. 现状与调整依据

以下为调整前的源码设置，不代表已经完成浏览器性能测量。

| 项目 | 调整前 | 主要问题 |
| --- | --- | --- |
| 问答正文 | 显式覆盖为 13px | 协议解读、分析等长内容偏小 |
| 预览和多数卡片 | 13px，辅助信息常为 11～12px | 字段核对吃力、层级接近 |
| 全屏内容列 | 最大 70rem | 宽表格有空间，但文字行过长 |
| 首问 | 13px，单行省略 | 较长的业务问题看不到关键条件 |
| 停止生成 | 消息区域上方独立状态条 | 与发送入口分离，显隐改变正文高度 |
| 图标入口 | 个别点击区域为 20px | 点选精度要求较高 |
| 布局过渡 | 多处 240ms | 已有拖动禁用过渡，但减少动态效果覆盖不完整 |

16px 是本产品面向长文阅读的设计取值，并非人体工学或无障碍标准规定的统一字号。实际观感需要使用中文长文、公式与表格验证。

## 3. 字体、颜色与间距

### 3.1 字体层级

| 内容 | 字号 | 行高 | 说明 |
| --- | --- | --- | --- |
| 用户消息、AI 正文 | 16px | 28px | 中文长文优先，不额外增加字间距 |
| 输入文字 | 16px | 26px | 与正文大小一致，保留输入区密度 |
| 正文一级/二级/三级标题 | 22 / 19 / 16px | 1.5 | 600 字重，避免 Markdown 标题随着正文无限放大 |
| 卡片正文、表格、首问、历史标题 | 14px | 22～24px | 字段值和公式完整呈现 |
| 状态、说明、时间 | 12～13px | 18～22px | 关键错误和限制说明不能弱化成装饰文字 |
| 窗口标题 | 16px | 24px | 与正文区分靠字重和位置 |

中文使用系统无衬线字体栈；代码保留等宽字体。业务录入文本主要是自然语言，展开内容优先使用正文的字体，不强制所有文字等宽。

### 3.2 颜色

| 用途 | 基准 |
| --- | --- |
| 正文 | `#303655` |
| 标题 | `#20243b` |
| 辅助说明 | `#626b80` |
| 次要文字 | `#6b728c` |
| 主操作、链接、焦点 | `#5159cf` |
| 卡片背景 | 白色 |
| 内容区背景 | `#fbfcff` |
| 分隔线 | `#edf0f7` / `#e3e7f4` |

错误、成功、等待均带明确文字；颜色不能成为唯一判断依据。有效信息的普通文本以 4.5:1 对比度为检查基线。禁用、装饰等例外按具体用途判断。

参考：[W3C 文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

### 3.3 间距与点击区域

- 窗口内容左右边距：正常 20px，窄视口 16px。
- 卡片内边距：12～16px；相邻卡片间距至少 8px。
- 正文段落间距约 12px；标题上方留足分段距离，首标题不额外制造大块空白。
- 常用图标按钮点击区域至少 32×32px，图标本身约 16～18px。历史行更多入口至少 28×28px。
- 键盘焦点必须可见；悬停才出现的操作在键盘聚焦时也能看到。

点击区域的产品取值高于 24 CSS px 的基础目标；是否满足无障碍要求还需要结合间距和例外判断。参考：[W3C 点击目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

## 4. 布局与阅读宽度

默认浮窗宽 640px、抽屉宽 560px，保留现有拖动、调整尺寸、全屏、布局记忆与边界约束。

正文、表格、图表、预览卡片与输入共用最大 960px 的居中内容列，取消正文单独的 800px 限制，让混排内容边界一致。浮窗和抽屉内随可用宽度收缩；超宽表格仍在自身区域横向滚动。

```text
┌ 标题 / 当前页面 ─── 新建 · 历史 · 布局 · 全屏 · 关闭 ┐
│                                                     │
│  问题                                               │
│  回答文字：与表格共用内容列                                  │
│  ┌ 表格 / 图表 / 填写预览：共用列宽 ───────────────┐ │
│  └────────────────────────────────────────────────┘ │
│  等待回答 / 本轮生成失败（按实际状态显示）            │
│                          返回最新位置               │
├─────────────────────────────────────────────────────┤
│  附件队列                                           │
│  输入校验 / 业务数据读取提示；必要时重试              │
│  添加附件  输入内容                         发送/停止 │
│  快捷键与 AI 内容提醒                                │
└─────────────────────────────────────────────────────┘
```

宽表格在自己的容器内横向滚动，不撑破窗口，也不让整段对话横向滚动。长编号和公式只有在必要时换行，不全局使用 `word-break: break-all`。

## 5. 各区域规范

### 5.1 顶部工具栏

保留全部操作。标题与当前页面名称允许收缩和省略，并提供完整提示；操作区不被挤出窗口。窄窗口优先缩短新建按钮的视觉标签，保留可访问名称与提示。低频操作收进更多菜单作为后续选项，仅在现有布局仍拥挤时实施，不为菜单增加状态复杂度。

图标按钮保留原生 `title` 和 `aria-label`，统一文案与点击范围。顶部工具栏不使用组件 Tooltip：此前实测点击全屏等按钮后会有提示残留，影响布局切换体验。布局切换、恢复、关闭继续使用原有处理函数。

### 5.2 欢迎页与首问

每批仍显示最多三条；问题来源和优先级不变。首问最多显示两行，保留完整问题提示。点击只预填，不直接发送，并将焦点放入输入框。

文案使用用户能理解的任务描述，例如“正在协助：新增规则”“可以围绕当前页面提问”。避免把“未接入表单”“问答模式”等实现术语作为欢迎页主要说明，也不能暗示未具备的能力。

### 5.3 输入与状态

沿用 SDK 输入框、附件队列、自动增高和输入法保护。正文和输入统一 16px，正文行高 28px、输入行高 26px；输入框最多约五行，超出后内部滚动。

| 状态 | 主操作 | 反馈 |
| --- | --- | --- |
| 空输入 | 发送不可用，附件沿用现有处理 | Enter 发送，Shift+Enter 换行 |
| 可发送 | 发送 | 显示原有说明 |
| 生成中（含前端工具等待） | 停止生成 | 等待首段内容时在回答区显示；输出开始后由正文和运行光标反馈 |
| 附件上传中 | 保留原提交守卫 | 附件卡片显示原有上传动画；SDK 会移除失败项，失败文件名和原因在附件队列附近、输入框上方说明 |
| 业务数据读取中 | 保留原提交守卫 | 输入框上方显示真实读取状态及已有重试入口 |
| 出错 | 保留原恢复路径 | 生成错误位于本轮回答末尾，输入校验错误在输入框上方，工具错误留在原卡片 |

停止统一调用项目现有 `stopRun`，使用项目的完整运行状态，不能只依赖 SDK `agent.isRunning`。不增加第二个停止入口。

输入框下方只放快捷键与 AI 内容提醒，不承载生成状态或业务错误。输入框上方的提示纳入 SDK 覆盖层高度测量，长错误允许换行。历史分页错误继续放在历史加载位置。执行阶段只使用真实状态，不推测“正在解析”等后端未提供的进度；流式正文出现后不重复展示“正在生成”。

仅主动选择首问时明确聚焦输入；生成、切页、工具结束不能持续抢走业务表单或历史搜索的焦点。

### 5.4 结果与预览卡片

统一卡片字号与间距，保留全部数据。字段名、最终值、不写入原因清晰可辨；复制、下载等操作有明显可用和完成状态。

确认操作仍属于对应预览卡片。长预览优先通过清晰的操作区改善定位；暂不直接增加吸底确认按钮，以免遮挡字段或让用户未核对就操作。只有实测证明必要且不遮挡内容时，再单独实施吸底方案。

待确认、正在填入、已填入、历史只读继续来自原有状态，不能以视觉优化改变可操作条件。历史预览不能恢复成可写。

### 5.5 滚动与动效

保留现有历史滚动控制：向上阅读停止跟随、分页恢复锚点、尺寸变化补偿。新内容到达不能强迫正在阅读历史的用户跳到底部。

拖动和调整尺寸时无缓动；窗口/抽屉/全屏切换继续采用约 240ms 的过渡，先验证稳定性再考虑缩短。`prefers-reduced-motion: reduce` 覆盖窗口位移、尺寸、圆角及助手自己的辅助过渡。

“更丝滑”以不丢阅读位置、不出现双滚动条、不反复跳动为验收重点；未经性能录制，不宣称帧率提升。

## 6. 两步实施

| 步骤 | 内容 | 完成条件 |
| --- | --- | --- |
| 第一步：阅读与视觉 | 字体、颜色、间距；正文与表格统一列宽；首问两行；标题收缩；按钮与卡片一致性 | 三种窗口形态可读，无内容遮挡和整窗横向溢出 |
| 第二步：交互与稳定性 | 停止归入输入；状态就近显示；首问聚焦；减少动态效果；回归滚动和切态 | 单一停止入口、状态不抢焦点、消息与预览行为保持原样 |

不在本轮新增主题切换、字号设置面板、虚拟列表、后端进度协议或卡片折叠业务规则。

## 7. 验收矩阵

| 维度 | 必查项 |
| --- | --- |
| 窗口形态 | 640px 浮窗、560px 抽屉、全屏、最小可调整宽度 |
| 屏幕 | 常用桌面尺寸；100% 和 125% 浏览器缩放，缩放不能只用 DPR 模拟 |
| 内容 | 中文长协议、五段阶梯公式、宽业务表格、长字段值、附件、录入 Prompt 卡片 |
| 输入 | 首问预填不发送；焦点可继续输入；中文候选确认不误发；Shift+Enter 换行；长输入自动增高 |
| 状态 | 生成/停止、附件上传与失败、业务数据读取与重试、错误长文案 |
| 滚动 | 阅读历史时流式输出、向上分页、返回底部、窗口切态 |
| 预览 | 确认与禁用条件不变、填入后状态正确、历史只读 |
| 可访问性 | 可见键盘焦点、按钮可访问名称、浅色文字、减少动态效果 |

检查方式：真实 TypeScript 检查与构建；真实组件的浏览器预览与交互验证；涉及会话、填写行为时运行已有回归测试。隔离样例可以验证组件布局与交互，不替代真实宿主、实际模型输出和业务接口联调。

### 阅读与反馈位置修订

正文与输入调整为 16px，表格和卡片保留 14px。下方说明为 13px / 20px。生成失败与等待反馈属于回答区；发送前校验和业务数据读取属于输入框上方；附件上传和工具结果复用原有组件状态。保留单一停止入口、原生 title、原有提交守卫与滚动策略。

本次修订已通过 TypeScript 检查、修改文件的 ESLint 检查及文档站构建。Edge 隔离样例实测正文 16px / 28px、输入 16px / 26px、表格 14px；验证了等待提示在正文出现后消失、生成错误在本轮回答末尾、上传失败显示文件名且位于输入框上方、业务数据重试位置、唯一停止入口、输入法组合事件、向上阅读不跳动和 420px 窄抽屉。未连接真实模型与业务接口，人工验收边界同上。

### 全屏列宽修订

用户反馈正文与表格宽度差异影响混排观感，现统一内容列最大宽度为 960px，移除正文独立限宽。此前记录的 800px / 1120px 为旧版实测值。本次按用户要求仅修改，未运行构建、测试或浏览器验证，待用户实际体验确认。
