# 系统介绍与架构

AI 助手是平台的共享能力。用户可以围绕页面提问、解读业务数据、从文字或附件整理表单，也可以让助手打开目标页面后继续填写。

本文档面向前端开发者，按 **2026-10-09 工作区源码**整理。应用入口、模型配置和权限以实际部署为准。

## 系统由什么组成

| 部分 | 技术与位置 | 负责什么 |
| --- | --- | --- |
| 平台宿主 | `yoohoo-pass/frontend`，React、qiankun | 加载子应用、提供页面目录和导航、登记当前页面能力 |
| 助手前端 | `ai-agents/frontend`，React、CopilotKit、Zustand | 对话窗口、会话、附件、前端工具、填写预览和确认 |
| 业务应用 | BMS / OMS / TMS 等，`src/assistantBinding` | 描述页面字段、读取数据、请求候选、执行原页面联动 |
| AI 后端入口 | `ai-agents/java-agents/l1-agent`，Java、Spring Boot、AgentScope | L1 对话编排、模型调用、附件解析、会话与工具协作 |
| 场景服务 | L3 场景 Agent 与业务服务 | 查询或处理对应领域的业务任务 |

前后端通过 **AG-UI** 交换消息、工具调用和执行结果。L1 可通过 **A2A** 调用场景 Agent。CopilotKit 是前端对话与工具接入框架，不是整个系统，也不是业务计算引擎。模型由后端配置，不在业务页面固定指定。

## 各层职责

| 层 | 关键代码 | 责任 |
| --- | --- | --- |
| 宿主 | PASS `frontend/src/microapps/` | 加载助手和业务应用，注入客户端，提供页面导航 |
| 桥接 | PASS `frontend/src/ai/assistantBridgeProtocol.ts` | 协议 v2 注册表，维护路由、会话和激活目标 |
| 助手界面 | ai-agents `frontend/src/components/Assistant/AssistantHost.tsx`、`ChatSession.tsx` | 窗口、对话、上下文和工具注册 |
| 填写引擎 | 同目录 `fill.ts`、`dropdown.ts`、`Preview.tsx` | 转换输入、解析候选、生成预览、确认前复核和回读 |
| 业务适配 | 业务应用 `src/assistantBinding/` | 将原页面转换成助手可读取和写入的能力 |

PASS 提供常驻容器；窗口形态、拖动和全屏由助手子应用处理。旧的宿主对话组件不能当作当前主链路的接入入口。

## 三个常见名词

- **target**：助手当前操作的页面实例，不是业务单据 ID。
- **IFormPort**：页面登记的能力对象，包括 `describe/read/write/ensureOptions/context` 等方法。只问答页面也可登记，但 `kind` 为 `chat`。
- **draft**：一次填写预览，绑定生成时的目标、会话和表单快照。

业务客户端由 PASS 经 qiankun 的 `props.assistant` 注入。它登记 IFormPort；助手再从桥取得该对象，调用页面自己的读写函数。模型只看到可序列化的字段描述，不会拿到这些函数。

## 为什么候选和联动留在业务应用

候选应使用页面原来的请求方法、租户与筛选参数。选择字段后的业务联动，也应调用页面已有逻辑。适配层负责连接这些能力，不另写一套 AI 专用业务规则。

字段推导依赖本应用 React 控件的模块身份，因此 `assistantBinding` 需要放在业务应用内；填写引擎仍只在助手应用维护。

## 生命周期

1. 子应用挂载时连接宿主客户端。
2. 页面满足 `enabled` 条件后注册目标。
3. 路由与 keep-alive 激活状态决定哪些目标当前可用。
4. 入口显式选择目标，或宿主选择唯一候选。
5. 页面关闭、切换或卸载后，停止使用旧目标；子应用卸载时断开连接。

同一页面多张表单宜合成一个 target。多个独立目标同时存在时，按钮必须传 `targetId`；同路由多实例要传稳定且可区分的 `instanceId`。

## 数据分别放哪里

| 内容 | 通道 |
| --- | --- |
| 固定解读规则、页面能力事实 | `context`，进入系统上下文 |
| 当前表单字段和值 | `get_current_form_context` |
| 完整业务记录、用户可编辑文本 | `initialData` → `get_conversation_data` |
| 用户文件 | 上传附件 → L1 提取正文或视觉转录 |
| 给用户看的快捷提问 | `questions`，不是系统提示词 |

业务快照和可确认草稿有内存生命周期。历史消息能回看，不等于可以恢复原来的页面操作状态。

## 能力边界


| 功能 | 用户能做什么 | 业务侧要提供什么 | 边界 |
| --- | --- | --- | --- |
| 通用问答 | 在助手中提问 | 已配置的后端能力 | 不代表能访问所有业务数据 |
| 页面问答 | 围绕当前页面解释和咨询 | chat target、受控 context；完整数据走快照 | 不写表单 |
| 表单填写 | 从文字或附件生成拟填内容，修订后确认 | 字段、当前值、候选和联动能力 | 确认只写页面，不自动提交 |
| 页面跳转 | 查找并打开注册页面 | 权限菜单或静态 manifest | 目录存在不代表有操作权限 |
| 业务数据解读 | 点击单据后解读完整数据 | `initialData.load` | 不会仅凭列表摘要自动得到全部明细 |
| 后端业务查询 | 查询既有业务或运行场景任务 | L1/L3 已接入的工具、业务服务和权限 | 不是新增前端配置就能获得的能力 |
| 连续操作 | 解读后跳到新页面并继续填写 | 会话快照、目标路由、目标表单就绪 | 不能沿用来源页字段写目标页 |

## 一次填写会发生什么

1. 读取真实表单字段、当前值和候选说明。
2. 模型整理逻辑输入，前端解析候选并生成预览。
3. 用户可以修订，也可以确认可写项目。
4. 确认时复核页面与字段状态，执行写入和原页面联动，回读比对。
5. 用户在原页面继续校验、试算或提交。

“可填入 N 项”只说明这些项目可以落表，不表示合同所有条款都已覆盖。字段问题、缺失信息和其他费用条款需要单独说明。

## 附件辅助填写

文件先在 L1 文件层解析，再供模型理解和映射。PDF 文本层提取、扫描识别和结构化字段映射是不同步骤。上传成功不保证正文完整，也不保证表格列关系正确。

页面可以维护有适用条件的解释 context，例如区分货物总量和每趟计费数量。不能把某个案例的物料 ID、日期或金额当作所有文件的默认值。

## 会话与预览

助手支持历史会话、向上加载消息和预览回看。当前内存中的草稿才可能确认；历史预览只读。连续修订的展示取决于消息中保存的替代关系，旧记录可能无法完整恢复关联。

`newSession` 是入口的会话选择意图；当前会话未使用时可复用，并非每次点击都生成一条空会话。

## 前端工具与后端场景

前端工具存在，不代表 L1 一定选择它。实际选择还受后端系统提示、页面 context 和场景工具描述影响。若本来想填表却进入业务查询，先检查真实工具调用与 L1 路由，不要继续盲目增加页面提示词。
